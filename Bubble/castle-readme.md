# Bubble — Material Siege 0.4.4

Play: https://arisconstantinou.github.io/Bubble/?v=0.4.4

Source remains **only in `Bubble/` on `main` of `ArisConstantinou/ArisConstantinou.github.io`**. This is the desktop/mobile interface fix on top of the approved 0.4.3 outer firing ring, not another combat redesign.

## Fixed: mobile joysticks appearing on desktop

The previous desktop CSS only reduced the opacity of the thumb controls. It did not hide them. This was reproduced using the exact 0.4.3 Pages artifact at commit `1bd138cbc94eaac94f61805b8e64776e866874df`.

Desktop now hides both virtual joysticks, the touch FIRE circle, and the touch jump/gait buttons. A compact clickable tool dock shows PATH, GRIP, the current tool, body region or construction form, connection and ammunition/reload, with keyboard hints. The grade action appears while PATH is enabled. The charge meter remains available above the dock. Desktop notifications describe mouse/keyboard controls, not thumb gestures.

**Desktop controls:** WASD/arrows move, Shift sprints, Control sneaks, Space jumps, mouse aims. Tap/release left mouse for a normal SPLAT; hold/release for a charged shot; hold Alt for an arc. FLOW/ERASE use a held mouse button. T changes tool, 1–4 chooses body region, E or right-click connects/releases, R reloads, B toggles PATH, V changes grade, G toggles GRIP, X selects eraser, F selects wall construction, C changes camera, I opens BAG and Escape pauses. These actions remain functional with the touch circles hidden.

## Input device, not window size

Initial UI mode uses the browser's primary pointer capability. Merely exposing `maxTouchPoints`, or making a PC window narrow, does not enable the mobile joysticks. A large tablet still keeps its touch interface.

On hybrid devices, a real touch selects the touch layout; actual keyboard/mouse use selects desktop. Switching input modes cancels stale held actions without spending ammunition. Compatibility mouse events generated by a touch are ignored, and mouse movement does not steal control from held native touch contacts. Ordinary left/right-thumb interactions retain separate owners and do not perform a global reset.

The interface uses an explicit `data-input-mode` attribute, set by the input controller. Desktop CSS defaults to hidden touch circles until initialization, avoiding a flash of mobile controls on PC. All original touch layout styles remain unchanged.

## Mobile firing ring is preserved

The inner disc only aims, including full aiming speed. Drag the same finger into the purple outer ring for normal SPLAT shots; return inside to stop firing while still aiming. The left joystick only moves. FLOW/ERASE use the outer ring as a continuous trigger; STRAND remains a separate intentional action. The separate charge/lob button retains priority over normal ring fire.

The existing ring thresholds, cadence, independent native Touch identifiers, cancellation handling and viewport-resize disarming remain. Text selection, copy/cut/paste, dragging and touch callouts remain blocked inside the game page, not the browser interface.

## Gameplay and saves are unchanged

This patch does not alter the castle, enemy placement or behavior, material collision rules, equipment, Forge, objectives or boss. `bubble-character-v3` remains the character save key on the same browser/origin. Refresh and verify **0.4.4**; do not clear site data, which would remove the local character save. A reload starts a fresh live siege, not a fresh character. No external runtime dependency, analytics or cloud service was added.

Gum remains the bounded static scalar-volume simulation already in the game. It is not a full viscous-fluid solver and does not simulate structural collapse after support removal. These limits are unchanged.
